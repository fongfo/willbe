# Willbe — 家庭韧性规划平台 产品设计与开发计划

> 基于 `project/Prototype Family Contingency Platform.html` 原型扩展而成。
> Jira 项目：[WB (Will Be)](https://growth-more.atlassian.net/jira/software/projects/WB/boards/34/backlog)
> GitHub：https://github.com/fongfo/willbe

## 1. 产品定位

面向东南亚华人家庭的"家庭韧性规划"平台。核心价值：把分散在家人脑中的"万一发生意外，家人该找谁、去哪找文件"的信息，系统化整理成可信、可移交、AI辅助补全的计划。

**首发市场**：东南亚/华人市场（马来西亚优先，新加坡等多国扩展），需多语言、多法域合规设计。

## 2. 核心功能模块（沿用原型六步流程）

1. **家庭成员管理**（角色/关系/所在地）
2. **信任联系人**（主+备份，建议最少2个）
3. **资产引用**（银行/保险/房产/投资/加密货币）——仅存引用信息，**不存密码/余额/私钥**
4. **检查频率 + 云盘集成**（Google Drive/OneDrive/Dropbox/iCloud）
5. **就绪度评分 + Gap 列表**
6. **紧急情况移交视图**

## 3. Web3 / 区块链设计

**模式**：托管钱包（Web3 in Web2）——底层公链，但密钥由平台/钱包服务商托管，用户无需理解私钥概念。

**链选型建议**：Polygon（EVM生态成熟、Gas低、东南亚钱包/交易所支持好）。

**上链内容**：仅哈希/存证凭证。
- 用户计划数据生成摘要哈希（如 Merkle root）+ 时间戳 + 版本号，写入链上 "Proof of Plan" 合约
- 原始数据加密存放在数据库/对象存储，**不上链**
- 紧急移交（emergency handoff）的验证与授权动作同样生成链上存证，作为未来可信凭证

**关键设计约束**：链上不可篡改 vs PDPA被遗忘权的冲突 — 链上只留哈希（不含可识别信息），真实数据可在数据库中删除/解除关联，满足用户删除请求。

**托管钱包服务商候选**（待技术选型）：Privy / Web3Auth / Magic

## 4. AI 功能设计（v1 核心卖点）

### AI 客服
- 范围：产品引导（如何添加家庭成员/资产）、答疑（为什么需要多个信任联系人）、紧急情况操作指引
- 技术：基于 Claude 的 RAG 客服，知识库 = 产品文档 + FAQ + 本地法规摘要
- 渠道：App 内嵌聊天 + 官网客服入口
- **边界声明**：不提供财务/法律/保险建议

### AI Gap 分析
- 现有原型的 `computeAssessment()` 是硬编码规则引擎（if/else 打分）
- 升级为「规则引擎 + LLM 解释层」：规则引擎产出结构化 gap 列表，LLM 转化为自然语言、个性化建议、优先级排序
- 后续迭代：基于家庭画像（成员年龄、资产类型组合）的动态评分模型
- **边界声明**：仅评估"信息完整度"，不提供保险/投资/法律建议，避免触及需牌照的金融意见监管

## 5. 技术架构

| 层 | 选型 |
|---|---|
| 移动端 App | React Native |
| 后端 | Node.js + Express |
| 数据库 | PostgreSQL（敏感字段加密）+ Redis |
| 区块链层 | 独立 anchoring 微服务：生成哈希、调用链上合约、托管钱包 SDK 集成 |
| AI 层 | 独立服务封装 Claude API（客服 RAG + Gap 分析解释），pgvector 做知识库检索 |
| 官网 | Next.js 静态/SSR 营销站，不涉及用户数据 |

## 6. 路线图

> 周期为粗估，需按实际团队规模调整。

## 7. 主要风险

- 链上不可篡改 vs 数据被遗忘权 — 已用"仅哈希"方案规避，需法务最终确认
- 托管钱包意味着平台对用户私钥/未来 token 化资产有保管责任，需考虑保险/担保机制
- AI 幻觉风险用在家庭重大决策场景 — 需要人工复核入口 + "AI生成内容"标识
- 金融建议边界：AI/产品需明确声明非财务/法律/保险建议，避免触犯需牌照监管
